# Overseer Chat Message Handling & Clipboard Specification

This document provides the formal specification for how chat messages, thinking texts, and pre-tool reasoning are formatted, displayed, and copied to the clipboard in the Overseer project.

---

## 1. Message Structure & Thinking Encapsulation

In Overseer, AI reasoning chunks and thinking tokens are encapsulated within HTML `<div>` tags directly in the message payload:

```html
<div class="ai-thought">

Reasoning or thinking content generated by the model...

</div>
```

### Origins of `<div class="ai-thought">`
1. **Streaming Thinking Tokens**: When AI models with native thinking capabilities (e.g. Gemini 2.5 / 3.0, Claude 3.7 Thinking) stream `thinking_chunk` events, `ChatComponent` and `ChatService` wrap them in `<div class="ai-thought">\n\n...\n\n</div>\n\n`.
2. **Pre-Tool Preamble / Reasoning**: When a model outputs text before initiating a tool call (`tool_start` / `tool_call_complete`), the text is classified as reasoning and automatically wrapped in `<div class="ai-thought">` before persisting to database or pushing to the chat history.

---

## 2. UI Display vs. Visibility Toggle

The user setting `showThoughtsAndTools` controls whether thinking blocks and tool calls are visible in the chat UI:

- **Mode 0**: Minimal (Hide both thinking text and tool calls).
- **Mode 1**: Tools Only (Hide thinking text, show tool calls).
- **Mode 2**: Thoughts Only (Show thinking text, hide tool calls).
- **Mode 3**: Full (Show both thinking text and tool calls).

### CSS Visibility Mechanism
The visibility of thoughts in the UI is controlled via CSS in `chat.component.scss`:
```scss
.messages.hide-thoughts ::ng-deep .ai-thought {
  display: none !important;
}
```
Because thinking blocks are part of `msg.content` (rendered via `MarkdownPipe`), they exist in the DOM and in the raw message string regardless of the visibility setting.

## 3. Clipboard Copy Specification

> [!IMPORTANT]
> **Core Requirement**: When a user clicks the copy button (`.copy-btn`) on any Overseer message (completed or actively streaming), **thought texts must NEVER be copied to the clipboard**. Only the main response content from the AI must be copied, regardless of the `showThoughtsAndTools` setting.

### Rules:
1. **Strip All Thinking Blocks**: All `<div class="ai-thought">...</div>` blocks and their enclosed contents must be completely stripped before writing to the clipboard.
2. **Streaming Resilience**: During active streaming, thinking tags might not yet be closed (`<div class="ai-thought">` without a matching `</div>`). The stripping logic must cleanly remove from `<div class="ai-thought">` to the end of the string (`(?:<\/div>|$)`).
3. **Empty Output on Pure Thoughts**: If a message contains *only* thinking content (e.g. while the model is still in its reasoning phase), copying produces an empty string (`""`).
4. **Code Block Preservation**: Intentional multi-line blank spacing, indentation, and formatting inside code blocks (```...```) must be preserved 100% untouched.
5. **Whitespace Normalization**: Gaps left by multiple consecutive or interleaved thinking blocks in normal markdown text must be collapsed to standard paragraph breaks (`\n\n`), and leading/trailing whitespace must be trimmed.
6. **Cross-Platform Line Endings**: Sanitization must handle both Windows CRLF (`\r\n`) and Unix LF (`\n`) line endings.
7. **Tool Result Separation**: Individual tool call outputs are copied separately via their dedicated copy button (`.tool-copy-btn` invoking `copyToolResult(tc.result, ...)`), which copies only `tc.result`.

---

## 4. Implementation Pattern

The static method `ChatComponent.stripThoughts` in `chat.component.ts` implements this specification:

```typescript
static stripThoughts(text: string | null | undefined): string {
  if (!text) return '';
  // 1. Strip all closed and unclosed thinking blocks case-insensitively
  const stripped = text.replace(/<div\s+class=["']ai-thought["']>[\s\S]*?(?:<\/div>|$)/gi, '');
  
  // 2. Split around code blocks to protect code formatting
  const parts = stripped.split(/(```[\s\S]*?```)/g);
  for (let i = 0; i < parts.length; i += 2) {
    // 3. Normalize line endings and collapse excess newlines in non-code parts
    parts[i] = parts[i].replace(/\r\n/g, '\n').replace(/\n{3,}/g, '\n\n');
  }
  
  // 4. Join and trim leading/trailing whitespace
  return parts.join('').trim();
}
```

### Usage in Copy Handler:
```typescript
async copyToClipboard(text: string, index: number | null) {
  try {
    const cleanText = ChatComponent.stripThoughts(text);
    await navigator.clipboard.writeText(cleanText);
    // ... update visual copied state
  } catch (err) {
    console.error('Failed to copy text: ', err);
  }
}
```

### Usage in Streaming Avatar State:
`ChatComponent.updateHasRealContent()` uses `ChatComponent.stripThoughts(this.streamingMessage).length > 0` to accurately detect when non-thought response tokens have started arriving, preventing premature avatar transitions.
