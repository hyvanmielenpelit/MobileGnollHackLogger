1. The data sensitivity ladder

This is the classification that decides what Overseer claims to support. Find your own data on it before you decide what to send.

    @for (rung of ladder; track rung.tier) {
  1. {{ rung.tier }} {{ rung.meaning }} {{ rung.verdict }}

The declared ceiling is your own personal data. Overseer is built to hold the notes, logs and documents you keep about yourself, and it claims nothing above that line.

The technical controls are category-agnostic. Encryption does not care whose personal data it protects, and every control described on this page protects another person’s data exactly as well as your own. What differs above the ceiling is legal and procedural rather than technical:

  • For documents identifying other people, Overseer becomes responsible for someone who has no account here and cannot be identified — so an access or erasure request from that person cannot be honoured.
  • For regulated data, there is no business associate agreement or equivalent with any AI provider, and no certification.

The ladder is therefore a disclosure mechanism, not a second set of controls. Uploading a document that mentions someone else is treated as the expected case rather than an edge case: the answer is identical protection plus honesty about the ceiling, which is what this section is. Overseer does not scan your uploads to detect personal data, and that is a decision rather than an omission — detecting it would mean reading the very content the detection was meant to protect.

4. What stays readable even in a confidential chat

The rule: only a named set of things is encrypted, and everything outside that set stays plain text. The encrypted set is a message’s content, a tool call’s arguments, result and error text, the chat’s title, the name you gave an attachment, and an attachment’s bytes on disk. Everything else about the chat is readable to anyone with database or file access. In a normal chat nothing is encrypted at all, content included.

That rule is stated instead of a list of database columns on purpose. A hand-written list of forty fields goes stale on the next schema change, and a stale list is worse than a rule because it reads as complete. What the rule leaves exposed is easier to judge by what someone could learn from it, so here it is grouped that way. The most consequential entry is the first one.

Google Fonts is not a subprocessor. Cinzel and Lato are served from Overseer’s own origin, so loading a font sends nothing to Google. Google Fonts transmits every visitor’s IP address to a third party on every page load, before any consent, which is why the font files are hosted here instead.

The provider’s own web-search tool is not a separate recipient: the query goes to the provider that is already answering the turn, and it searches on its own account. It is withheld entirely in a confidential chat.
